# Failure-Mode Catalog — Frontend

The recurring ways AI-generated frontend code is *locally correct but broken in production*. Each entry: the trap, why AI defaults to it, and the defuse. Used in Gate 3 (UI state machine + failure modes) and Gate 4 (risk register).

The meta-pattern: **AI models the happy visual path; production UIs are state machines under async, failure, and assistive tech.** Most of these are async-timeline bugs, missing states, or category errors about where trust lives.

React APIs are named below because they are the most common shape, but every entry has a direct equivalent elsewhere — Vue's `computed`/`watch`, and plain DOM's handlers and observers. The exact API, lint rule, and version floor for your stack live in the reactivity tier: `mir-frontend-react`, `mir-frontend-vue`, `mir-frontend-vanilla`. Versions cited here were checked on 13 Aug 2026.

---

## 1. Derived state stored in its own state variable

Computed values (filtered lists, totals, formatted strings, boolean flags derived from props) stored in a separate `useState` — or a separate `ref` — and synced with an effect or watcher. **Why AI defaults here:** it cargo-cults the "state = data" mental model and writes an explicit sync because "that's how you keep things up to date." **Defuse:** if a value can be computed purely from existing state or props during render, compute it inline — no second state variable, no effect. Reach for manual memoization only with profiling evidence (see #14 for what the React Compiler actually does with it). The effect is always the wrong tool for a derived value; in Vue, `computed` is the right one.

## 2. Async race / stale response

A search or fetch fires on each keystroke or dep change; the last fired request wins but may return first if a slower earlier request resolves late — silently displaying stale data. No cleanup on unmount or dep change. **Why AI defaults here:** it writes `fetch(…).then(setState)` in a single shot and never models overlapping calls. **Defuse:** cancel in-flight requests via `AbortController` in the effect cleanup; alternatively (and preferably for most data-fetching) use TanStack Query, which deduplicates and discards stale results by default. Its cancellation is **not** automatic: it hands your `queryFn` an `AbortSignal` and you must forward it (`queryFn: ({ signal }) => fetch(url, { signal })`) or the request keeps running. Never trust that the last-initiated request finishes last.

## 3. useEffect overuse, effect-driven derived state, and infinite loops

Effects used to compute derived values, to synchronize two pieces of state, or written with unstable object/array/function literals in the dependency array — producing infinite render loops. **Why AI defaults here:** `useEffect` looks like "do something when X changes," which matches every conditional-update intuition. **Defuse:** apply the single rule — *if a value is derivable in render, there is no effect.* Effects are for synchronizing with external systems (timers, subscriptions, DOM APIs, analytics) only. Unstable deps: stable identity via `useCallback`/`useMemo` (or the Compiler) before putting a function or object in a dep array; primitives derived in render are stable by construction. The Vue shape of this is `watchEffect` under-subscribing — its dependency set is re-collected on every run, so a branch not entered this run subscribes to nothing, and anything read after an `await` inside it is never tracked — plus the flush timing that decides whether the callback reads pre-update or post-update DOM.

## 4. Stale closures in callbacks, timers, and subscriptions

An event handler, `setTimeout`, or subscription callback captures state or props at creation time. By the time it fires, the values are stale — the closure never sees updates. **Why AI defaults here:** JavaScript closures are transparent; AI writes callbacks that look correct at the call site but freeze a snapshot of the world. **Defuse:** either re-create the callback when its dependencies change, with matching cleanup, or read the value through a mutable holder so the callback always sees the current one. Each tier has a purpose-built API for the second option — React's `useEffectEvent`, for instance — and the tier skill names it. Do not hand-roll the holder when the library ships one.

## 5. Hydration mismatch

SSR-rendered HTML diverges from the client's first render because the component reads `Date.now()`, `Math.random()`, `window`, `navigator`, locale, or any value that differs between server and client environments. **Why AI defaults here:** it writes a component that "works in the browser" without modeling that the same function runs twice — first on the server, then re-executed on the client. **Defuse:** keep render functions pure and environment-agnostic; gate browser-only reads behind an effect that runs after mount, or behind the framework's explicit client-only boundary (`<ClientOnly>`, `ssr: false` on a dynamic import). **`'use client'` is not that boundary** — a Client Component is still prerendered on the server for the initial load, so a `window` read in its render body runs on the server and mismatches. `suppressHydrationWarning` is a narrow escape hatch for genuinely unavoidable differences (e.g. timestamp formatted for the user's locale) — it is not a general silence switch.

## 6. Cross-user data bleed from module-scope state on the server

Any object created at module scope on a server-rendered path is created **once per process**, not once per request, so every visitor shares it. One user's data is served to the next. The shapes: a `QueryClient` at the top of a file, a `ref`/`reactive` exported from a composable, a hand-rolled store singleton, a `const cache = new Map()`, or an SDK client configured with the current caller's token. **Why AI defaults here:** library docs show `new QueryClient()` at the top of a file for the client-side case, and in the browser modules re-initialize on every page load, so the pattern looks correct in dev. **Defuse:** construct every cache, store, and API client inside the request/render path — per request, never at module scope. A stateless, user-independent singleton (a connection pool, a compiled schema) is fine; anything holding a user's data or token is not.

**How you catch it:** it never reproduces with one browser in dev. Two identities, two browsers, one production process, reload. Then grep for module-scope `= ref(`, `= reactive(`, `new QueryClient(`, `= new Map(`, and bare `let` in shared composable/util/store files.

## 7. Unsafe SSR dehydration (XSS via inline script)

Query/state snapshots serialized into HTML via `JSON.stringify` and injected into a `<script>` tag or a `data-` attribute — without escaping `</script>` sequences or HTML-encoding the content. A user-controlled string in the cache can escape the script block. **Why AI defaults here:** `JSON.stringify` "produces valid JSON" and AI treats validity as safety. It is not. **Defuse:** use a safe serializer that escapes `<`, `>`, and `&` in JSON strings before injecting into HTML (`devalue`, or the framework's own payload serializer — Next's RSC payload, Nuxt's `__NUXT_DATA__`). TanStack Query's `dehydrate()` is **not** that: it returns a plain object, not an escaped string, so whatever writes it into HTML still owns the escaping. Never hand-roll `<script>window.__STATE__ = ${JSON.stringify(data)}</script>`.

## 8. INP-blocking interactions

Heavy synchronous work — large list renders, complex calculations, synchronous API calls, unthrottled scroll handlers — runs directly in an event handler or synchronous state update, blocking the main thread and pushing Interaction to Next Paint (INP) past the 200 ms budget. **Why AI defaults here:** it solves for functional correctness; visual latency is invisible in a test. The same budget is blown by **layout thrashing**: reading a geometry property (`offsetWidth`, `getBoundingClientRect()`, `scrollTop`, `getComputedStyle`) after a style write forces synchronous layout, and inside a loop that is one forced layout per iteration. **Defuse:** defer non-urgent rendering with `startTransition` (marks the update interruptible) or `useDeferredValue` (defers a value until the urgent render finishes); batch all geometry reads, then all writes; for genuinely CPU-heavy work move it off the main thread with a Web Worker, or `scheduler.yield()` where it is available — support is not universal, so feature-detect and fall back. INP ≤ 200 ms is a Core Web Vital, having replaced FID; it is measurable only in RUM, not in CI.

## 9. UX state explosion — missing states

Only three states modeled: loading / success / error. A production UI also needs: **empty** (no results yet, vs "search returned zero"), **stale** (showing cached data while refreshing), **retrying** (bounded retry in progress), **offline** (network gone), **optimistic** (mutation submitted, not confirmed), **rolling back** (optimistic update rejected), **permission-denied** (403 differs from generic error), **expired-auth** (redirect, not generic error). **Why AI defaults here:** loading/success/error is the minimal demo; the rest emerge only from real usage. **Defuse:** Gate 3 requires an explicit UI state machine with every reachable state named. Each state must have a defined UI: skeleton, empty-state illustration, inline error with retry, banner, disabled form, or redirect. States not modeled will be silently wrong.

## 10. ErrorBoundary and Suspense placement errors

A single `<ErrorBoundary>` at the root catches all errors but shows a full-page crash for a sidebar widget's data failure. `<Suspense>` wrapping with `useSuspenseQuery` without a prefetched query causes a server-then-client double waterfall: the server suspends, the client suspends again. **Why AI defaults here:** one boundary works; the ergonomics of granular placement require deliberate architecture. **Defuse:** place a loading and an error boundary around each independent data subtree so a failure in one region does not blank the whole page. Prefetch queries in Server Components or route loaders so the client finds data already in the cache and does not re-suspend. Not every tier has this: Vue's `<Suspense>` is still documented as experimental, and plain DOM has no boundary mechanism at all — there you render each state yourself. Check the tier skill before designing around a boundary.

## 11. Fetch waterfalls

Child component fetches only after parent renders; sequential `await fetch()` chains inside a single loader; data loaded inside components that render inside other data-loading components. **Why AI defaults here:** component-local fetching is the obvious, self-contained pattern — it composes cleanly in isolation. **Defuse:** hoist fetches to the route loader or Server Component so sibling fetches fire in parallel (`Promise.all`). TanStack Query's `useSuspenseQuery` in parallel (not nested) or prefetch-then-read avoids the sequential trap. The rule: data dependencies should be declared at the route/page level, not discovered lazily as the tree renders.

## 12. XSS via a raw-HTML sink, unsafe markdown, and client-side secret/auth leakage

Passing unescaped user content to a raw-HTML sink — React's raw-HTML prop, `<iframe srcDoc>`, Vue `v-html`, Angular `[innerHTML]`, plain `innerHTML`/`insertAdjacentHTML` — injects arbitrary markup. A `<script>` inserted that way does not run, which is why the bug survives review; `<img src=x onerror=…>` and `<svg onload=…>` do. Markdown renderers configured to emit raw HTML are the same risk, and LLM output is user content arriving by another route. Separately: any build-time public env var (`NEXT_PUBLIC_`, `VITE_`, `PUBLIC_`, `NUXT_PUBLIC_`, `REACT_APP_`) is inlined into the bundle, so a secret placed there is published — and rotating it needs a rebuild while every shipped build keeps the old value. Client-side authorization (hide a button, skip a route, lazy-load the admin chunk) is a UX hint; the server must enforce the same rule per object. **Why AI defaults here:** raw-HTML rendering "just works" for trusted content; public-vs-private env prefixes are easy to confuse; and visible UI suppression feels like access control. **Defuse:** render structured elements, or sanitize with DOMPurify — floor **3.4.13** (3 Aug 2026), pinned exactly, never `IN_PLACE: true`. Add a CSP without `'unsafe-inline'` and, where the stack supports it, `require-trusted-types-for 'script'` so a missed sanitizer throws a `TypeError` at the sink instead of executing. Grep the **built output** for secrets in CI. Replicate every authorization decision server-side.

## 12b. Flash of wrong theme (FOWT) on SSR dark mode

Dark-mode preference read from `localStorage` after hydration causes the page to flash light → dark on load. **Why AI defaults here:** `localStorage` is browser-only, so it is naturally deferred to `useEffect` — which fires after paint. **Defuse:** inject a blocking inline `<script>` in `<head>` (before the CSS) that reads `localStorage` and applies the theme class synchronously, before the browser paints. Alternatively use a CSS media query (`prefers-color-scheme`) as the default so no JS is needed for the initial paint; layer the user-preference override on top. Never read theme from `localStorage` in a `useEffect` if avoiding flash matters.

## 13. Hallucinated UX

Pagination, autosave, debounced search, sortable columns, undo/redo, optimistic updates, and retry buttons appear in the implementation without ever being specified. AI invents plausible, production-looking defaults. **Why AI defaults here:** these patterns are common enough to feel like "obviously needed" — and they complete the feature ergonomically. **Defuse:** Gate 1 asks explicitly: "Does this list paginate? If so, cursor or offset? Debounce on search? Client-side or server-side sort? Autosave or explicit submit? Optimistic or pessimistic mutation?" Every answer not given by the user must be surfaced as an Assumption Ledger entry with a recommended default — never silently implemented.

## 14. Compiler era: blind useMemo/useCallback is a liability, but not for the reason usually given

Manual `useMemo` and `useCallback` wrapped around every value "for performance". The common correction is wrong: **React Compiler 1.0.0 does not delete your manual memoization — it preserves it**, on the assumption you had a reason. The cost lands elsewhere. When a manual `useMemo`'s dependency array is incomplete, the compiler can no longer follow the data flow through it and stops optimizing that code, so you end up with hand-written memoization that is wrong *and* no automatic memoization compensating for it. **Why AI defaults here:** training data through 2024 rewarded manual memoization everywhere, and the Compiler's GA post-dates most patterns the model learned. **Defuse:** confirm whether the project opted in (`babel-plugin-react-compiler` 1.0.0, or the framework's built-in flag). Write plain, pure components in *new* code. In *existing* code, react.dev is explicit: leave correct manual memoization in place, or test carefully before removing it — "removing it can change compilation output." Leaving an *incorrect* one is the expensive case, because that is what stops the compiler optimizing the surrounding code. Lint with `eslint-plugin-react-hooks` **7.1.1** — v7 enables the compiler rules inside `recommended`, including `preserve-manual-memoization`, so a v6 → v7 upgrade turns CI red on code that passed before; schedule it rather than being surprised. Use `"use no memo"` only for genuinely incompatible code. Vue's analogue is different: `computed` already caches, and the bug there is a side effect inside the getter, not a missing memo.

## 15. Supply-chain and dependency hygiene

AI generates `import` statements for npm packages that do not exist, pins nothing (an unpinned `^` range drifts into a breaking or compromised version), and skips `npm audit`. Bundle size gets no budget. **Why AI defaults here:** package names are plausible, semver ranges look conventional, and bundle size is invisible in a text diff. Two distinct risks follow. **Slopsquatting:** attackers register the plausible names AI invents, so a hallucinated import can resolve to real malware on the next install. **Namespace compromise:** trusted publishers get taken over — CVE-2026-45321 was malware in 42 `@tanstack/*` packages that exfiltrated cloud credentials, GitHub tokens, and SSH keys, reached through GitHub Actions OIDC token extraction. A well-known namespace is not evidence of safety. **Defuse:** verify every package name against the registry before committing; commit the lockfile and install with `npm ci`; keep install scripts off (`ignore-scripts=true`) so a transitive `postinstall` cannot run in the job that builds your bundle; run `npm audit --audit-level=high` in CI; set a bundle budget (first-load JS ≤ ~100 KB compressed as a starting point) and enforce it in CI. Provenance attestations reduce risk without eliminating it — pinning plus audit stays mandatory. Pipeline-side controls (OIDC instead of long-lived keys, SHA-pinned actions, artifact signing) are `mir-devsecops`.

## 16. Teardown that was never written

A listener on `window` or `document`, an `IntersectionObserver`/`MutationObserver`/`ResizeObserver`, a `setInterval`, a WebSocket, or a subscription is created and never removed. The callback stays alive, and its closure keeps every variable it captured alive with it — including DOM nodes that are no longer in the document. The symptoms arrive late: memory climbing over a long session, a handler firing against a component that is gone, duplicate handlers after a re-mount, polling that continues on a screen nobody is looking at. **Why AI defaults here:** setup and teardown are written in different places, and the generated example is the setup half. It also looks correct in a test that mounts once and never unmounts. **Defuse:** every subscription gets its removal written in the same edit. With a framework, that is the unmount hook — and watch the cases where unmount never fires: a cached/kept-alive component is deactivated, not destroyed, so cleanup placed in the unmount hook never runs. Without a framework, one `AbortController` per component instance and a single `abort()` removes every listener registered with its signal. Confirm rather than assume: mount and unmount the component N times, then take a heap snapshot and filter for detached nodes.
